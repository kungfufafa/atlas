Atlas can run as a Telegram bot so you can chat with the same agent from your phone, desktop Telegram, or a shared group.

The mental model is simple:

- Telegram is a **channel** for Atlas
- The bridge talks to the same Atlas server as the web app
- Pairing links a real Telegram user to your Atlas access

## What Telegram supports

With Telegram enabled, users can:

- chat with a Atlas profile in a private chat
- use the bot in Telegram groups
- receive outbound webhook notifications in a group or topic
- switch org and profile with commands
- send text, photos, voice notes, and supported documents
- receive Markdown-style rich replies when Telegram accepts the formatting

## Channel controls

Workspace administrators can open **Integrations → Telegram → Channel controls** to control what the bot may do in that workspace.

1. Set **Channel enabled** and **Approval buttons** as needed.
2. Under **Native actions**, enable the actions your team needs. The replying profile also needs the `channel_action` tool. Telegram supports reactions, polls, editing or deleting its own session messages, pins, forum topic creation or changes, and saved media delivery. Topic actions require a forum supergroup and the bot's Telegram permissions.
3. Use **Direct messages**, **Groups**, **Room rules**, and **Sender rules** to restrict senders, workspace roles, tools, and actions. Choose **Save controls**.

Rules apply together with **Access mode** and workspace permissions. A denial takes precedence. **Inherit** uses broader or default settings; an empty specified allowed list permits nobody, while an empty blocked list blocks nobody. A room rule can use a chat ID, topic ID, or `*`.

Groups normally require a mention or reply. An administrator can set **Groups → Require mention or reply → Disabled** to permit unaddressed messages that pass the other rules. Telegram must still deliver those messages to the bot; check Group Privacy below.

### Answer questions and approvals

When the agent presents choices, tap the buttons and then **Submit answers**. Questions can allow one or several choices. Type a reply when you need a custom answer. Pending approval cards offer **Approve** and **Deny**.

Controls belong to the original sender, workspace, conversation, and topic. Old or replaced cards cannot submit another answer or approval. If access changes, start from the current conversation instead of reusing an old card.

### Photos, video, and audio replies

Static WebP stickers are sent to the agent as images. MP4 clips up to **60 seconds** and **25 MB** are represented by up to four sampled frames; their audio is not transcribed. Those frames do not represent every moment. Animated and video stickers are rejected with a message.

Saved MP3/M4A audio, Ogg Opus voice notes, and MP4 video can be returned using Telegram's native media presentation. Voice notes remain message-based conversations; the Telegram bridge does not join live voice calls.

## Step 1: Create a bot with BotFather

Every Telegram setup starts with a bot token from `@BotFather`.

1. Open Telegram and search for `@BotFather`
2. Send `/newbot`
3. Choose a display name
4. Choose a username that ends with `bot`
5. Copy the bot token

Keep the token secret. Anyone with the token can control your Telegram bot.

## Step 2: Save Telegram settings in Atlas

Open **Integrations → Telegram** in the Atlas web app, then:

1. Paste the bot token
2. Choose the default Atlas profile for Telegram replies
3. Save

![Paste the bot token from @BotFather on Integrations → Telegram](/screenshots/telegram-bot-token.png)

When you save for the first time, Atlas can generate a chat access code for linking your Telegram account.

## Step 3: Enable audio transcription for voice chat

Telegram voice notes and audio files are turned into text before they are sent to the agent.

To enable that:

1. Open **Settings → LLM providers** and configure a provider model that supports audio transcription
2. Go to **Settings → Capability routing**
3. Under **Audio transcription**, choose the primary model
4. Optionally add fallback models, then select **Save**

If no eligible model appears, confirm that the provider and transcription model are configured for the active workspace. Without this setting, text chat still works, but Telegram audio messages will not be transcribed for the agent. See [Providers — Route provider capabilities](/providers#route-provider-capabilities) for fallback behavior and troubleshooting.

## Step 4: Pair your Telegram account

Pairing is required so random Telegram users cannot talk to your internal Atlas bot.

1. Copy the chat access code from **Integrations → Telegram**
2. Start a private chat with your bot
3. Send the chat access code as a normal text message

After a successful match, that Telegram user is linked and the chat access code is cleared.

![Generate a chat access code, then message it to your bot in Telegram](/screenshots/telegram-pairing.png)

### Why pairing exists

The bot token only connects Atlas to Telegram.

Pairing connects **your Telegram user account** to Atlas permissions.

Your workspace role still applies after pairing. Removing a member or changing their role stops their active turns and pending approvals in that workspace. In denylist mode, a blocked user cannot use a valid chat access code until an administrator removes the block.

That means Atlas can:

- identify which Telegram user is talking
- allow private chat safely
- apply the right org and profile access

## Step 5: Start the Telegram bridge

For local development, start it from the repo root:

```bash
bun run dev:telegram
```

The bridge uses long polling and forwards Telegram messages to your Atlas server.

If the Atlas server is not already running, the bridge will try to start it.

For production, start the Telegram bridge worker from the **Integrations** page in the Atlas web app instead of using the dev command.

## Optional: Direct allowlist instead of pairing

Atlas also supports allowlisting Telegram user IDs directly.

This is useful when you want to pre-authorize specific users without the one-time pairing flow.

To add users from the dashboard:

1. Open **Integrations → Telegram**
2. In **Allowed users**, click **Manage**
3. Paste a numeric Telegram user ID and click **Add**

To paste raw Telegram update JSON instead:

1. Open **Integrations → Telegram**
2. In **Allowed users**, click **Manage**
3. Click **Import JSON**
4. Paste the raw Telegram update JSON
5. Click **Add user**

Use the Telegram user's `from.id`, not their `@username`.
When you paste raw JSON, Atlas reads `message.from.id` and shows the username when it is present.

For example, in this Telegram update payload:

```json
{
  "from": {
    "id": 213193924,
    "username": "ahmadrosid"
  }
}
```

The allowed user ID is:

```text
213193924
```

You can also configure allowed users through `TELEGRAM_ALLOWED_USER_IDS` for environment-based deployments.

## Step 6: Configure Telegram privacy mode for groups

Telegram bots start with **Group Privacy** enabled. This is the most common reason a bot seems fine in private chat but not in groups.

If you want mention-based group usage to work reliably:

1. Open `@BotFather`
2. Open your bot settings
3. Disable **Group Privacy**
4. Remove the bot from the Telegram group
5. Add it back again

That re-add step matters because Telegram may keep the old delivery behavior for bots already in the group.

## Configuration notes

Atlas stores Telegram bridge settings under its local config directory.

Important values include:

- bot token
- default Telegram profile
- chat access code
- paired user IDs
- allowed user IDs from the dashboard allowlist

Environment-based setup is also supported. The main env var is:

```text
TELEGRAM_BOT_TOKEN
```

Atlas also supports:

```text
TELEGRAM_ALLOWED_USER_IDS
ATLAS_TELEGRAM_PROFILE_ID
```
