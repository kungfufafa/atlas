## Before you start

You need:

- An LLM provider API key (see [Providers](/providers))
- [Bun](https://bun.sh) if you run from source — or use [Docker](/docker)
- **LibreOffice** for PowerPoint, Word, and Excel previews and thumbnails. Docker images already include it. From source:

```bash
# macOS
brew install --formula libreoffice

# Debian / Ubuntu
sudo apt-get install -y libreoffice-writer libreoffice-impress libreoffice-calc fonts-liberation
```

## Choose a deployment path

### Option 1: Docker

For a single-container deployment:

```bash
docker pull ghcr.io/kungfufafa/atlas:latest
docker run -d -p 4310:4310 -v atlas-data:/atlas/data --name atlas ghcr.io/kungfufafa/atlas:latest
```

Open `http://localhost:4310`. See [Docker](/docker) for build-from-source, volumes, and production notes.

### Option 2: Local development

Clone the repository and install dependencies:

```bash
git clone https://github.com/kungfufafa/atlas.git
cd atlas
bun install
bun run dev:web
```

Open:

- Dashboard: `http://localhost:3000`
- API server: `http://127.0.0.1:4310`
- API docs: `http://127.0.0.1:4310/docs`

If you only want the API server:

```bash
bun run dev:server
```

On first run, the dashboard opens the setup wizard. Provider settings are saved in `~/.atlas/config.ini`.

### Option 3: VPS with PM2

On a server with [Bun](https://bun.sh):

```bash
git clone https://github.com/kungfufafa/atlas.git
cd atlas
bun run pm2:deploy
```

That installs dependencies, builds the dashboard, and starts Atlas under PM2. Open `http://YOUR_SERVER:4310` and complete the setup wizard.

Useful later:

```bash
bun run pm2:logs
bun run pm2:stop
bun x pm2 save && bun x pm2 startup
```

`pm2 startup` keeps Atlas running after a reboot. Put a reverse proxy in front if you want HTTPS on a domain.

## First-time setup

After Atlas is running:

1. Open the dashboard
2. Create the first admin account and first organization
3. Configure your model provider
4. Create or review profiles
5. Send a test message to the default profile

See [First-time setup](/first-time-setup) for the wizard walkthrough and [Providers](/providers) for supported LLM backends.

If the dashboard spinner never finishes, the browser is often waiting on an uncompressed JavaScript bundle (~4 MB). After you rebuild the web app, restart the Atlas process. Check the public URL, not only localhost:

```bash
curl -sSI -H 'Accept-Encoding: gzip' https://YOUR_HOST/assets/index-*.js | grep -i content-encoding
```

That must show `gzip`. If it does and the spinner still sits there, hard-refresh or clear the browser cache — an older uncompressed file can stay cached.
