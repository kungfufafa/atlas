## Export

Superadmins can export local Atlas data from **Settings → Export ZIP**.

The export is a `.zip` backup of the configured Atlas data root, which defaults to `~/.atlas` and follows `ATLAS_CONFIG_DIR` when set.

Treat export ZIPs as sensitive. They can include:

- Provider settings and API keys
- Auth data
- Org and profile workspaces (soul files, memory, artifacts)
- Org-level `MEMORY.md`, `memory-archive/`, and `memory-history/` (see [Org memory](/org-memory))
- Custom tools and skills
- The local SQLite database when it lives under the Atlas root

## Move a single profile

A profile-pack ZIP is a safer, narrower option when you want to copy one agent
instead of restoring the entire Atlas installation. On **Profiles**, a
Workspace Admin can export a standard profile, switch to another workspace,
and import it as a new standard profile. Superadmins can do the same after
switching into the workspace.

Profile packs exclude Atlas-managed provider credentials, MCP configuration and
secrets, Composio connections, generated artifacts, and archived memory.
Host-level custom JavaScript source is excluded from Workspace Admin exports
and can only be included by a Superadmin.
Assignments reconnect only to matching resources that already exist in the
destination workspace. User-authored soul, memory, knowledge-base, and skill
text is included and may itself be sensitive.

See [Profiles](/profiles#move-one-profile-between-workspaces) for the complete
contents and import behavior.

## Import

Importing is a whole-install restore:

1. Preview the ZIP first
2. Confirm restore to replace the current local data root

Plan for downtime during restore. This replaces the active data root rather than merging individual records.

On a fresh install, you can also restore during [first-time setup](/first-time-setup) before creating a new admin account.

## Docker volumes

When Atlas runs in Docker, persist `/atlas/data` with a named volume or bind mount. Back up that volume (or use Export ZIP from the dashboard) before upgrades or migrations.

See [Docker](/docker) for volume setup.
