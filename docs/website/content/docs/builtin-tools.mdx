Builtin tools are the actions a profile is allowed to take.

The mental model is simple:

- A profile can only use the tools assigned to it
- Different profiles can have different permissions
- Tool access is one of the main ways you control risk

Superadmins and Workspace Admins manage tool definitions under **System → Tools** and assign them to profiles in the active workspace.

## Why tools matter

The same model behaves very differently depending on its tools.

For example:

- A writing bot may need no tools at all
- A research bot may need web search, web fetch, and knowledge base search
- An ops bot may need file access and email
- A power-user bot may need skills and MCP servers

Give each profile the minimum tool set it needs.

## Parallel execution

When the model requests multiple tool calls in one turn, Atlas can run them concurrently — but only when **every** call in the batch is marked `parallelSafe`.

| Parallel-safe builtins | Sequential (default) |
|------------------------|----------------------|
| `read_file`, `search_files`, `knowledge_base_search`, `web_search`, `web_fetch`, `sub_agent` | `bash`, write/edit/delete file tools, email, Composio, MCP, session-state tools, and the rest |

If a turn mixes parallel-safe and sequential tools — for example `read_file` and `bash` together — the whole turn runs sequentially.

Custom JavaScript tools under `~/.atlas/tools/` default to sequential. Export `parallelSafe = true` from the module to opt in.

Custom JavaScript tools also default to no automatic retries. For an idempotent tool, export `retrySafe = true` to retry transient failures at most twice, after 500 ms and 1 second. Do not enable it for payments, messages, record creation, or any operation that could repeat a side effect.

Parallel execution speeds up multi-file research and lets a parent agent delegate several independent `sub_agent` tasks at once. See [`sub_agent`](#sub_agent) below.

The `sub_agent` tool is seeded but **not** auto-assigned — Workspace Admins opt in per profile. Super Agent also receives `bash`.

## Choosing tools for a profile

Good starting patterns:

- **Simple chat agent**: no extra tools
- **Research agent**: `web_search`, `web_fetch`, `knowledge_base_search`, optionally `sub_agent` for parallel deep dives
- **Knowledge agent**: `knowledge_base_search`, file tools, bundled system skills
- **Ops agent**: file tools, bundled `save-artifact` skill, `email`
- **Delegation agent**: `sub_agent` for in-process research/review/planning subtasks
- **Coding agent (Super Agent or custom)**: `bash` + `coding-agent` skill

## Work with everyday files

Attach a document in web chat, WhatsApp, Telegram, or Discord and describe the
result you need. Atlas keeps the original file available for processing and saves
edits as a new version by default. For example:

- “Update the status table in this Word report and keep the logo and header.”
- “Revise slide two and its speaker notes in this PowerPoint.”
- “Combine these PDFs, then send pages three through five as a separate PDF.”
- “Update this Excel input, recalculate the totals, and preserve the customer IDs.”

Word and PowerPoint edits support text and simple tables while preserving other
parts of the file. PDF extraction identifies which pages were read and includes
the names and values of ordinary PDF form fields. Spreadsheet
results distinguish stored formulas from verified calculations, and CSV imports
preserve leading zeroes and long identifiers unless you explicitly request a
numeric conversion. For decimal-comma data, specify the decimal separator when
requesting numeric columns.

The four bundled file skills guide the agent through checking its output. If an
existing profile cannot use a file tool, a Workspace Admin can assign it under
**System → Tools**. Existing custom tool selections are kept when Atlas updates.

Scanned PDFs can use OCR when Tesseract and its requested language are installed.
PDF merging retains bookmarks, internal links, and embedded attachments. Word
replacements can record tracked changes while retaining earlier reviewer history.
Workbooks with charts support cell edits; their charts refresh when reopened in
Excel. Atlas reports chart calculations as unverified until a suitable application
refreshes them. Signed PDFs, PDF forms during merging, tracked moves in Word,
and workbook layout changes involving charts still need specialized handling.
Formatting checks require a renderer; text extraction alone cannot verify layout.

Channel upload limits still apply. If a returned file cannot be attached, Atlas
keeps the saved artifact available and reports its location or available link.
Find saved results under **Files → Artifacts**. Temporary working copies of
uploaded inputs are not automatically sent back as new deliverables.

For photo edits in WhatsApp, Telegram, and Discord, Atlas instructs the agent to
use the original image and return a verified JPG or PNG. SVG remains available
for requested vector work, such as logos and diagrams. Raster tools can resize,
crop, and adjust images; generative changes such as replacing a scene need a
configured tool that accepts the source image. If that capability is unavailable,
the agent should explain the limitation instead of presenting a simpler effect
or an SVG wrapper as the finished photo. SVG uses the existing delivery options:
documents in WhatsApp and Telegram, and share links or **Files → Artifacts** for
Discord.

### Self-hosted file runtime

The Docker image includes LibreOffice for Office rendering and Excel
recalculation, Poppler and Tesseract with English and Indonesian OCR, and a managed
Python environment for file analysis and Pillow for raster image processing.
For a source installation, use Python 3.11 or later. Run the installer as the
same operating-system account that runs Atlas, with the same `ATLAS_CONFIG_DIR`
environment setting if your service uses one:

```bash
bash scripts/setup-file-runtime.sh
```

The script installs the libraries under `runtime/python` in Atlas's configuration
directory (`~/.atlas` by default). It checks dependencies and verifies that Pillow
can save and reopen both JPEG and PNG before reporting the runtime ready. Rerun
the installer when updating an existing source installation to add these libraries.

Atlas selects `ATLAS_PYTHON_PATH` first, then its managed runtime, then system
`python3`. A configured interpreter takes precedence even if the managed runtime
is installed. For a custom runtime directory, pass its absolute path to the
installer and set the printed `ATLAS_PYTHON_PATH` in the Atlas service environment.
Setting it only in an unrelated terminal does not update a running service.

Restart Atlas after installing or changing the runtime. For PM2 deployments,
reload the service with its updated environment; `bun run pm2:deploy` does not
install the Python runtime. To check the interpreter used by an agent with
**Python Execute** assigned, ask it to report `sys.executable`, import `PIL`, and
save and reopen a small JPEG and PNG in its workspace. A successful check in a
different shell or Python installation does not verify the agent's runtime.

LibreOffice is installed separately;
`ATLAS_OFFICE_CONVERTER_PATH` can select its executable. A missing calculation
engine is reported, and cached formula values are not treated as recalculated.

Source installations also need Poppler and Tesseract for OCR. Install the
Tesseract language packs needed by your team. `ATLAS_PDFTOPPM_PATH` and
`ATLAS_TESSERACT_PATH` can select their executables. Missing OCR dependencies
leave the affected pages marked as unread; Atlas does not claim complete coverage.

Rendering also needs fonts that cover the document's languages. The Docker
configuration includes Noto fonts for Arabic and CJK; source installations must
provide suitable fonts to LibreOffice.

Python and shell tools require macOS `sandbox-exec` or Linux Landlock ABI 3.
They can read and write the assigned profile and private temporary directory,
and read installed runtime libraries. They cannot use another profile's files
or the host account's login files. Execution is blocked when the filesystem
boundary is unavailable. Network access remains enabled; this boundary does
not provide a separate virtual machine or resource quota for each organization.

## Edit a spreadsheet efficiently

Ask for related value and layout changes together, such as “update the asset counts, format the header, and size the columns.” Atlas can apply these changes in one saved version while preserving your original. It verifies formula results after the final edits when LibreOffice is available.

If repeated restyling reaches the per-turn limit, Atlas stops and reports the latest saved workbook and unfinished work. Give concrete changes for the next request. On WhatsApp, `/stop` cancels current work and `/pause` keeps your conversation quiet until `/resume`; see [WhatsApp chat behavior](/whatsapp#chat-behavior).

## Memory workflows

Profile memory is not a separate builtin. Agents use `read_file`, `write_file`, and `edit_file` with two bundled skills:

| Skill | Purpose |
|-------|---------|
| `update-profile-memory` | Append facts and preferences to active `MEMORY.md` |
| `archive-profile-memory` | Move bullets to `memory-archive/` without deleting them |

Active `MEMORY.md` has a **4096-byte** soft limit. Default and super-agent profiles receive these skills when bundled skills are installed on the server. See [Bundled system skills](/skills#bundled-system-skills) for the full workflow.

## Artifact saves

Artifacts are files your agent creates and saves for you — reports, summaries, generated text, Word documents, and other outputs you can preview or download later from the dashboard Artifacts tab or from web chat.

They are not a separate builtin. Agents use `write_file` or `write_docx` with the `save-artifact` bundled skill under `artifacts/`. The skill also documents writing a `{filename}.atlas-meta.json` sidecar so the Artifacts tab shows MIME types and timestamps.

On web chat, `write_file` and `write_docx` saves under `artifacts/` appear as attachment chips on the assistant message. Click a chip to open a resizable preview panel with copy, download, and fullscreen:

On **WhatsApp**, Atlas attaches the file in the chat and does not post a share link or filename in the text. On **Telegram** and **Discord**, the same paired saves post a Publish share link after the agent reply; ask to “send the file” when you want a native attachment. See [WhatsApp](/whatsapp#supported-message-types), [Telegram](/telegram/chat#saved-artifacts-and-share-links) and [Discord](/discord#saved-artifacts-and-share-links).

### Edit an artifact manually

Workspace Admins and Superadmins can open a Markdown (`.md`, `.markdown`), CSV, or TSV artifact in **Files → Artifacts** or from its web-chat attachment, then select **Edit**. Markdown opens as source text; CSV and TSV files open as an editable grid. Select **Save** to refresh the preview or **Cancel** to discard the draft.

Atlas detects when the file changed after you started editing and keeps your draft instead of overwriting the newer version. Dashboard editing is limited to UTF-8 files up to 2 MB, 500 rows, and 50 columns. A larger or truncated preview remains available but its Edit action is disabled. Values beginning with spreadsheet formula characters are stored as text to prevent formulas from running when the CSV or TSV is opened elsewhere.

Published links are snapshots. Editing the source artifact does not change an existing public link; publish it again when you want to share the new version.

| Content type | Preview behavior |
|--------------|------------------|
| HTML (`.html`, `text/html`) | Sandboxed iframe render |
| Markdown (`.md`, `text/markdown`) | Rendered prose |
| Word (`.docx` from `write_docx`) | Server converts to Markdown for preview |
| JSON, code, plain text | Syntax highlighting or monospace block |
| Unknown extension | UTF-8 sniff — preview when the bytes look like text |

Legacy `.doc` (Word 97–2003) is not supported for generation or preview. Binary formats outside these paths show a download-only message.

## Coding agent

Repo coding work is not a separate builtin. Profiles with the `coding-agent` skill invoke Codex, Claude Code, OpenCode, pi, or Cursor Agent through `bash`. See [Coding agent](/coding-agent) for skill-driven install, multi-CLI choice, provider passthrough, and runtime behavior.

## Tool reference

### `write_file`

Write text to a file in the profile workspace.

| Parameter | Type | Required | Notes |
|-----------|------|----------|-------|
| `path` | string | Yes | Relative to profile workspace unless absolute |
| `content` | string | Yes | Text to write |
| `cwd` | string | No | Base directory within workspace; defaults to workspace root |

**Returns:** `{ path, bytesWritten }`

**Scope:** `~/.atlas/orgs/{orgId}/profiles/{profileId}/` and `~/.atlas/tools/` (custom JS modules)

**Restrictions:** Refuses binary document and archive formats such as Word, PowerPoint, Excel, PDF, and ZIP. Use the corresponding document tool to create a valid file.

**Availability:** When assigned to the profile.

### `write_docx`

Create a real Microsoft Word (`.docx`) document from Markdown content. Headings, bold/italic, lists, tables, and code blocks are converted. Use whenever the user asks for a Word document.

| Parameter | Type | Required | Notes |
|-----------|------|----------|-------|
| `path` | string | Yes | Must end in `.docx`; relative to profile workspace unless absolute |
| `markdown` | string | Yes | Markdown source for the document body |
| `cwd` | string | No | Base directory within workspace; defaults to workspace root |

**Returns:** `{ path, bytesWritten }`

**Scope:** Profile workspace only. Under `artifacts/`, existing files are not silently overwritten — Atlas picks a unique filename instead.

**Availability:** When assigned to the profile. Assigned to system profiles (`default`, `super_agent`) by default; assign manually to custom profiles when needed.

### `delete_file`

Delete a file from the profile workspace or custom tools directory.

| Parameter | Type | Required | Notes |
|-----------|------|----------|-------|
| `path` | string | Yes | Must be within allowed directories |
| `cwd` | string | No | Base directory within workspace |

**Returns:** `{ path, deleted: true }`

**Scope:** Profile workspace and custom tools directory only.

**Availability:** When assigned to the profile.

### `edit_file`

Edit an existing text file in the profile workspace using exact replacements.

| Parameter | Type | Required | Notes |
|-----------|------|----------|-------|
| `path` | string | Yes | Relative to profile workspace unless absolute |
| `edits` | array | Yes | One or more `{ oldText, newText }` replacements |
| `cwd` | string | No | Base directory within workspace |

Each `oldText` must be present once and edits must not overlap. Atlas applies all edits against the original file, then writes the result atomically after validation.

**Returns:** `{ path, replacements, bytesWritten, fuzzyMatches }`

**Scope:** Profile workspace and custom tools directory only.

**Availability:** When assigned to the profile.

### `read_file`

Read text from a file in the profile workspace.

| Parameter | Type | Required | Notes |
|-----------|------|----------|-------|
| `path` | string | Yes | Relative to profile workspace unless absolute |
| `cwd` | string | No | Base directory within workspace |
| `offset` | number | No | 1-based start line; default 1 |
| `limit` | number | No | Maximum lines to return |

**Returns:** `{ path, content, bytesRead, startLine, endLine, totalLines, truncated }`

**Scope:** Profile workspace and custom tools directory. Reading `config.ini` by basename is blocked.

**Availability:** When assigned to the profile.

### `search_files`

Search text in files under the profile workspace.

| Parameter | Type | Required | Notes |
|-----------|------|----------|-------|
| `query` | string | Yes | Keyword or regex pattern |
| `path` | string | No | Subdirectory or file within workspace |
| `glob` | string | No | Ripgrep glob filter (e.g. `*.md`) |
| `regex` | boolean | No | Treat query as regex; default true |
| `maxResults` | number | No | Default 50, max 200 |

**Returns:** `{ query, root, matches, matchCount, truncated }`

**Scope:** `~/.atlas/orgs/{orgId}/profiles/{profileId}/` only. Requires `rg` (ripgrep) on PATH.

**Availability:** When assigned to the profile.

### `knowledge_base_search`

Search uploaded knowledge base documents for relevant facts. The Knowledge tab can also show inherited URL sources, such as the Atlas documentation index at `llms.txt`; use `web_fetch` on that index and on specific `.md` pages — not `knowledge_base_search`.

When this tool is assigned and ready documents exist, Atlas retrieves likely excerpts before each factual answer across web chat, CLI, Telegram, WhatsApp, and Discord. The agent uses `knowledge_base_search` again when it needs a narrower or alternative query.

| Parameter | Type | Required | Notes |
|-----------|------|----------|-------|
| `query` | string | Yes | Keyword or regex pattern |
| `filename` | string | No | Filter to one source document (e.g. `report.pdf`) |
| `regex` | boolean | No | Default true |
| `maxResults` | number | No | Default 50, max 200 |

**Returns:** `{ query, root, matches, matchCount, truncated }` — empty matches when no ready document matches the filter.

**Scope:** Extracted text files stored under `~/.atlas/orgs/{orgId}/profiles/{profileId}/knowledge-base/`.

**Availability:** When assigned **and** at least one uploaded document has `status: "ready"`. Inherited URL sources do not require `knowledge_base_search`; they require `web_fetch` or `web_search`.

### `web_search`

Search the web for current information.

| Parameter | Type | Required | Notes |
|-----------|------|----------|-------|
| `query` | string | Yes | Search query |

**Availability:** When assigned **and** the configured provider is OpenAI or Anthropic with a valid API key. Not available on OpenRouter. On Gemini, web search is disabled when other local tools are present on the same turn.

### `web_fetch`

Fetch a single public HTTP(S) URL and return its content. HTML pages are converted to Markdown. Use for retrieving a known URL; use `web_search` when you need to discover sources.

| Parameter | Type | Required | Notes |
|-----------|------|----------|-------|
| `url` | string | Yes | Absolute `http://` or `https://` URL |
| `raw` | boolean | No | When true, return raw body without Markdown conversion; default false |

**Returns:** `{ url, finalUrl, status, contentType, bytes, content }`

**Behavior:** Follows up to 5 redirects. Request timeout 30s. Maximum response body 1 MB.

**Scope:** Public internet addresses only. Private, reserved, and localhost targets are blocked.

**Availability:** When assigned to the profile.

### `email`

List, read, search, and send email through the deployment mailbox configured in Settings.

| Parameter | Type | Required | Notes |
|-----------|------|----------|-------|
| `action` | string | Yes | `list`, `read`, `search`, or `send` |
| `folder` | string | No | Mailbox folder; default `INBOX` |
| `limit` | number | No | For list/search; default 20, max 100 |
| `uid` | number | Yes for `read` | IMAP UID |
| `query` | string | Yes for `search` | Subject/from/body search |
| `to` | string | Yes for `send` | Single recipient |
| `subject` | string | For `send` | Email subject |
| `text` | string | For `send` | Plain text body |
| `html` | string | No | Optional HTML body for send |

**Returns:** Structured JSON with `messages`, `message`, or `sent` — or `{ error: "..." }` on failure. Send body max 256 KB.

**Availability:** When assigned **and** the `[email]` section in `~/.atlas/config.ini` is complete. Omitted at runtime when incomplete (`omitUnavailableBuiltinTools`).

### `extract_document_text`

Extract text from a PDF, Word (`.docx`), or Excel (`.xls` / `.xlsx` / `.xlsm` / `.xlsb`) file when the agent needs the contents of a document that is not already in the chat.

Use it for:

- a `documentRef` returned by the email tool
- a stored chat attachment id
- a file in the profile workspace, such as `artifacts/report.pdf`

Files the user already sent in chat are converted automatically. Those show up as `[File: …]` text — the agent should read that instead of calling this tool.

| Parameter | Type | Required | Notes |
|-----------|------|----------|-------|
| `documentRef` | string | Yes | Email `documentRef`, stored attachment id, or a workspace path such as `artifacts/report.pdf` |

**Returns:** Bounded extracted text with filename, media type, truncation state, and warnings. Document content is untrusted.

**Limits:** Attachments larger than 5 MB are rejected. Extracted text is limited to 256 KB. OCR for scanned/image-only PDFs is not supported.

**Availability:** When assigned. It is independent of the built-in email mailbox configuration. Workspace paths work even when email is not set up.

### `bash`

Run a one-off shell command in the profile workspace and return stdout, stderr, and exit code.

| Parameter | Type | Required | Notes |
|-----------|------|----------|-------|
| `command` | string | Yes | Shell command to run |
| `cwd` | string | No | Working directory within the profile workspace |
| `timeoutMs` | number | No | Default 30000, max 1800000 (30 minutes) |
| `env` | object | No | Extra env vars merged at spawn time (string values) |
| `codingAgent` | boolean | No | When true, Atlas merges coding-agent spawn env for a command that starts with a known harness binary |

**Returns:** `{ exitCode, stdout, stderr, timedOut }`

**Coding-agent spawn env:** When the command starts with a known harness binary (`codex`, `claude`, `opencode`, `pi`, or `agent`), or when `codingAgent: true` is set with such a command, Atlas merges provider passthrough env vars on the server before spawn. `codingAgent: true` without a known binary fails closed. See [Coding agent — Provider passthrough](/coding-agent#provider-passthrough). Optional `env` keys are merged on top (credential keys cannot override passthrough).

**Working directory:** The profile workspace. Shell commands retain the server account's filesystem access. Do not use `bash` to create persistent tools or `.sh` wrappers — register JavaScript tools under `~/.atlas/tools/` instead.

**Availability:** When assigned to the profile. Super Agent receives `bash` by default. Required for the [coding agent](/coding-agent) workflow and the opt-in [agent-browser](/agent-browser) skill. Browser runs inherit optional host `AGENT_BROWSER_EXECUTABLE_PATH` / `AGENT_BROWSER_ARGS` when the operator configures CloakBrowser.

### `sub_agent`

Run a focused **same-profile** sub-agent for delegated work (research, review, planning, debugging). The parent receives a structured result to summarize for the user. This is a Atlas-native in-process agent loop — **not** the external coding-agent path (`bash` + `coding-agent`).

While a sub-agent runs, the chat UI shows a dedicated row with the task title and a **live status label** (for example "Reading SOUL.md", "Searching web · …", "Writing answer…"). When the run completes, the row shows the summary with an expandable full output.

Multiple `sub_agent` calls in one turn can run **in parallel** when the model batches them for independent tasks. Sub-agents still cannot nest — a sub-agent cannot call `sub_agent` again.

| Parameter | Type | Required | Notes |
|-----------|------|----------|-------|
| `task` | string | Yes | Clear instruction for the sub-agent |
| `context` | string | No | Optional scoped background (not full parent chat history) |
| `timeoutMs` | number | No | Default 300000 (5 min), max 600000 (10 min) |

**Returns:** `{ status, summary, output, error? }` where `status` is `success`, `fail`, or `timeout`.

**Limits (v1):**

- Same profile only — no cross-profile targeting
- One level of nesting — sub-agents cannot call `sub_agent` again
- No persisted child chat session — audit via parent tool result + server logs
- Child runs share the profile workspace; side effects persist even if the parent times out
- The sub-agent timeout still counts toward the parent chat stream budget (24 hours by default; self-hosted operators can lower it with `ATLAS_CHAT_STREAM_TIMEOUT_MS`)

**Availability:** When assigned to the profile (opt-in; not part of default custom profile assignments).

### `org_memory_search`

Search the organization's shared memory — live pinned bullets and the full archive — for facts relevant to a query. Use when the injected org memory summary is missing detail or when you need historical facts that were archived.

| Parameter | Type | Required | Notes |
|-----------|------|----------|-------|
| `query` | string | Yes | Text to search for across org memory bullets |

**Returns:** `{ query, matches }` — each match includes the source file and matching bullet text.

**Availability:** Automatically available on every profile for non-viewer roles. Not assigned from the dashboard. Viewers are denied. See [Org memory](/org-memory).

### `org_memory_list`

Return the organization's current live org memory content (pinned facts).

**Parameters:** None.

**Returns:** `{ content }` — raw markdown of the live org memory file.

**Availability:** Automatically available on every profile for non-viewer roles. Not assigned from the dashboard. Viewers are denied. See [Org memory](/org-memory).

## Configuration prerequisites

### Email

The `email` tool uses a deployment-global mailbox. Required keys in `~/.atlas/config.ini` under `[email]`:

- `imap_host`, `smtp_host`
- `username`, `password`
- Resolvable `from` address
- TLS flags as needed

Workspace Admins and Superadmins manage definitions under **System → Tools** and assign them from **Profiles**.

### Web search

Requires an OpenAI or Anthropic provider with a configured API key.

### Knowledge base

Upload documents via the profile dashboard or API. Search only indexes extracted text from documents with `status: "ready"`. Upload path: `~/.atlas/orgs/{orgId}/profiles/{profileId}/knowledge-base/`.

### Data portability

Superadmins can export and import the whole local Atlas data root from **Settings** in the dashboard.
Use **Export ZIP** to download a backup.
Exports are `.zip` backups and should be handled as sensitive files because they can include local auth, provider configuration, custom tools, skills, profile workspaces, and a local SQLite database.

Import first previews the ZIP manifest and restore impact.
Confirmed restore replaces the current local data root; selective merge, scheduled backups, cloud destinations, and encrypted archives are not part of the first version.

## Safety boundaries

File tools (`read_file`, `write_file`, `edit_file`, `delete_file`) are scoped to:

- **Profile workspace:** `~/.atlas/orgs/{orgId}/profiles/{profileId}/` (soul files, knowledge base, `artifacts/`, etc.)
- **Custom tools directory:** `~/.atlas/tools/` (follows `ATLAS_CONFIG_DIR` if set)

Agents save artifact files under `artifacts/` via the `save-artifact` bundled skill and `write_file`, not a dedicated builtin.

Path guards enforce:

- **10 MB** maximum file size for reads and writes
- No path traversal outside allowed directories
- No reads of `config.ini` by basename
- Blocked special paths (`/dev/`, `/proc/`, `/sys/`)

All builtin tool IDs are protected and cannot be deleted from the dashboard.

### Custom JavaScript isolation

Atlas runs each custom JavaScript tool in a separate process with an empty-by-default environment. Provider keys, `ATLAS_CONFIG_DIR`, and other server secrets are not passed to it. The process can read its own module and can read or write only the active profile workspace. Inspection never receives workspace access.

A flat `~/.atlas/tools/example.js` tool is intentionally a single-file module so it cannot read another workspace's flat tool source. If a tool needs relative imports or supporting files, put its entry module and dependencies together in a dedicated subdirectory and register that nested entry path. Atlas exposes only that subdirectory, read-only; package imports outside it remain blocked.

The filesystem boundary uses macOS `sandbox-exec` or Linux Landlock ABI 3. Linux hosts, including Docker hosts, need kernel 6.2 or newer with Landlock enabled. Atlas blocks custom JavaScript inspection and execution when that boundary is unavailable; it does not silently run the module with host filesystem access.

`ATLAS_ALLOW_UNSANDBOXED_CUSTOM_TOOLS=1` is an emergency compatibility escape hatch for an installation that already has an equivalent tenant-isolated VM or container boundary. Enabling it removes Atlas's filesystem isolation for custom JavaScript, so do not use it on a shared or multi-tenant Atlas host.
