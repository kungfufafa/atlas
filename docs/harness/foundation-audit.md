## Ordered follow-up and acceptance gates

1. **Finish foundation.** Resolve or explicitly report the disk gate; inventory open PRs and classify quality/merge readiness; establish truthful unit coverage, type/lint/build checks and exact post-merge revision evidence. A pending, skipped, blocked, or partial check is not a pass. This report does not certify the PR queue as empty or CI as trusted.
2. **First product cycle: provider recovery.** Port the behavior from Nakama [c23df86f / #1019](https://github.com/ahmadrosid/nakama/commit/c23df86fa09102a3724e8be1aaeb55fdd87251a1), adapting to Atlas permissions and current components. Source-only candidate until before/after browser proof is recorded.
3. **Next candidates, not concurrent cycles:** personalisation lifecycle, chosen setup-model persistence, then learning-contract consistency. Re-rank after the completed provider cycle; do not start them while its proof is incomplete.

Provider-recovery design constraints for the later cycle:

- Keep the account-not-configured guard. Remove provider availability as the reason to lock an existing account out of permitted application routes.
- Audit `LoginPage` and `InvitePage` post-auth redirects as well as `SetupGuard`; both currently send missing-provider users to setup. Preserve safe internal return paths and invite completion.
- Reuse the provider form in chat and task chat without losing the current draft/session. Preserve error, cancel, retry, and workspace-switch behavior; invalidate configuration state after successful save.
- Gate the connect action with existing `canCompleteWorkspaceSetup` semantics (platform admin or workspace admin). Keep server provider-write authorization. Members/viewers get an admin-needed notice and remain on routes their role permits.
- Browser proof must cover last-provider removal/recovery, login and accepted invite without a provider, admin/member/viewer behavior, cancel and failed save, successful save, and a real first reply using the mandated endpoint. Capture before/after screenshots on the local dev server. Mocked form success and source inspection cannot stand in for that model reply.
