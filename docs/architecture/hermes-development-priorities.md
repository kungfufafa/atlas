## Five next needs, in priority order

### 1. Restart-safe continuation of an active job and approval

**Gap:** chat evidence survives, but a live chat continuation still depends on in-process state. `ChatToolApprovalService` explicitly authorizes only the live waiting invocation; its pending map is lost on restart, and a later approval produces an honest 409 asking for a new action. Persisting execution checkpoints is not yet a complete worker that reconstructs and safely resumes that tool loop. The vulnerable interval between an external effect and its stored receipt also needs an explicit uncertain-result policy.

**Evidence:** [approval lifecycle](/Users/apriansyahrs/Documents/Code/atlas/apps/server/src/services/chat-tool-approval-service.ts:40), [missing live waiter](/Users/apriansyahrs/Documents/Code/atlas/apps/server/src/services/chat-tool-approval-service.ts:134), [tool-evidence checkpoints](/Users/apriansyahrs/Documents/Code/atlas/apps/server/src/services/session-persistence.ts:123), [in-memory active turn registry](/Users/apriansyahrs/Documents/Code/atlas/apps/server/src/services/session-turn-registry.ts:151). Hermes exposes transcript/session resume in [CLI lifecycle](/private/tmp/atlas-hermes-evaluation/source/hermes_cli/cli_session_mixin.py:136); that alone does not establish crash-safe exactly-once tool continuation either.

**Smallest honest evaluation:** three forced restart boundaries around one disposable external counter/file mutation: before effect, after effect but before receipt, and during approval. Reopen the same DB and native session, retain prior evidence, require a fresh valid approval where needed, and verify no silent repeated mutation. For an unconfirmed non-idempotent effect, explicit uncertainty/reconciliation is acceptable; do not promise exactly-once without a cooperating idempotency contract.

### 2. Long-context fidelity and recovery under real context pressure

**Gap:** metadata correctness and compaction existence are established; survival of user constraints, corrected facts and completed actions through compression remains unevaluated across provider ownership modes. Unknown context capacity should continue to mean unknown, not a guessed limit. The previous DeepSeek task runs did not test compression parity; Hermes's resolved heuristic capacity was different from Atlas's unknown policy.

**Evidence:** [instance-scoped compaction selection](/Users/apriansyahrs/Documents/Code/atlas/apps/server/src/providers/model-context.ts:6), [runtime-owned bypass](/Users/apriansyahrs/Documents/Code/atlas/packages/agent/src/chat.ts:393), [pruning/summarization and retained user/tool ranges](/Users/apriansyahrs/Documents/Code/atlas/packages/agent/src/history-compaction.ts:378). Hermes has rollback/cooldown state in [compression implementation](/private/tmp/atlas-hermes-evaluation/source/agent/conversation_compression.py:181) and provider-owned checkpoint logic in [native compaction](/private/tmp/atlas-hermes-evaluation/source/agent/native_compaction.py:110).

**Smallest honest evaluation:** one deterministic long conversation with a corrected durable fact, one nonrepeatable completed action, and a pending user constraint; force two compression boundaries on a declared small test capacity. Inject one failed summary and reopen once. Verify active facts, constraint retention, well-formed tool history and no repeated effect. Separately exercise a native-runtime context update/compaction event; later record one real pressure scenario per explicitly supported provider mode.

### 3. Completion evidence that survives tool failures

**Gap:** tool failures are now surfaced and recorded correctly, and truncated output has bounded recovery. A nonempty no-tool final response still sets the turn to completed without a generic check that requested artifacts or persistent effects actually exist. Prompt guidance alone cannot establish that a claim such as “saved” or “tests passed” is supported. Recovery should distinguish retryable reads from effects requiring verification or renewed approval.

**Evidence:** [tool error normalization](/Users/apriansyahrs/Documents/Code/atlas/packages/agent/src/tool-loop.ts:37), [bounded output recovery](/Users/apriansyahrs/Documents/Code/atlas/packages/agent/src/chat.ts:895), [final completion branch](/Users/apriansyahrs/Documents/Code/atlas/packages/agent/src/chat.ts:1122). Hermes offers a [passive verification ledger](/private/tmp/atlas-hermes-evaluation/source/agent/verification_evidence.py:1) and [bounded stop nudge](/private/tmp/atlas-hermes-evaluation/source/agent/verification_stop.py:158), but [verify-on-stop defaults off](/private/tmp/atlas-hermes-evaluation/source/agent/verification_stop.py:51); do not describe it as universally enforced.

**Smallest honest evaluation:** four scripted native trajectories: successful write; structured write failure followed by a misleading success final; stale test pass followed by another edit; and an unconfirmed external effect. Validate a receipt/verification summary tied to actual paths and action IDs, permit honest partial completion, bound any repair follow-up, and never re-execute a risky operation merely to improve success rate. Then use a small new held-out task set for the model's behavior, without modifying existing study scoring.

### 4. Measured procedural skill acquisition and later reuse

**Gap:** Atlas already has optional post-turn skill review, staged/admin promotion, discovery and outcome-based ranking. The missing evidence is that a newly learned procedure is selected and improves a genuinely new task after a fresh session, without embedding the target answer or generalizing a bad lesson. Default-off review and human promotion are deliberate tenant controls, not defects to bypass.

**Evidence:** [review eligibility/settings](/Users/apriansyahrs/Documents/Code/atlas/apps/server/src/services/skill-post-turn-review-service.ts:263), [review persistence boundary](/Users/apriansyahrs/Documents/Code/atlas/apps/server/src/services/skill-post-turn-review-service.ts:299), [matched skill/outcome selection](/Users/apriansyahrs/Documents/Code/atlas/apps/server/src/services/skills-service.ts:986), [default flag semantics](/Users/apriansyahrs/Documents/Code/atlas/packages/core/src/skills/post-turn-review.ts:6). Hermes [background review](/private/tmp/atlas-hermes-evaluation/source/agent/background_review.py:1) can fork the native agent and save memory/skills directly; this is a different promotion model, not demonstrated superior learning.

**Smallest honest evaluation:** teach three generic tool procedures with actual native tools and review enabled, apply only the declared approval/promotion path, then start empty-history sessions for three new variants. Compare retained-skill versus cold skill-store arms; include one deliberately unsuccessful procedure that must not become trusted guidance. Measure actual task correctness, selected skill hash, unnecessary tool work and mutation provenance. A saved SKILL.md alone is not success.

### 5. Provider and surface conformance as an ongoing product gate

**Gap:** implementing adapters does not establish the same user experience across API providers, native subscriptions, streaming and reconnects. Candidate 3 has explicit model identity, native context ownership and better failure/usage attribution; it still needs an end-to-end conformance matrix before offering a broad consistency promise. Equal reasoning quality across different models cannot be guaranteed by the harness.

**Evidence:** [ChatGPT fingerprinted resume](/Users/apriansyahrs/Documents/Code/atlas/apps/server/src/providers/subscription/chatgpt/runtime.ts:535), [completed usage and callback failure evidence](/Users/apriansyahrs/Documents/Code/atlas/apps/server/src/providers/subscription/chatgpt/runtime.ts:639), [strict Claude model selection](/Users/apriansyahrs/Documents/Code/atlas/apps/server/src/providers/subscription/claude/runtime.ts:571), [native context ownership](/Users/apriansyahrs/Documents/Code/atlas/apps/server/src/providers/subscription/claude/provider.ts:46). Hermes has provider-specific request recovery in [turn_recovery](/private/tmp/atlas-hermes-evaluation/source/agent/turn_recovery.py:1); that breadth is useful reference material, not evidence that any subscription can be used interchangeably.

**Smallest honest evaluation:** the same short four-step workflow per supported provider mode: one real protected tool result, approval wait, client disconnect/reconnect, and final delivery. Assert exact selected model, supported controls, one mutation, truthful terminal state, preserved receipt and unknown usage when unreported. Use recorded provider/runtime cassettes offline and one authorized real smoke per exact endpoint/model/runtime. Exercise the web/CLI flow, including approval and reconnect UI, before making UX claims. Keep quality evaluations by model/provider separate from transport conformance.

These needs support a consistent contract—clear capabilities, safe continuation, truthful completion and useful retained knowledge. They do not support declaring Atlas or Hermes the best harness, or claiming equal quality with any provider or subscription.
