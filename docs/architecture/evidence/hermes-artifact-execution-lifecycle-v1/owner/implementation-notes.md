# Trusted execution publication lifecycle — isolated component

The agent session options now accept a host-only lifecycle, separately from ToolContext. Both send/stream and API/native dispatch paths pass it to the mandatory protected executor. Each invocation receives a fresh publisher, and an inherited publisher is cleared to prevent accidental child/parallel ownership reuse. The host alone holds complete(), which receives the actual protected result before history distillation. Existing approval, schema, cancellation and tool guards still execute. Begin/completion/diagnostic observer failures do not replace the actual tool result or cause replay; diagnostic promises do not block the tool receipt.

The server adapter copies org/profile/session/actor/run/call identity before tool code runs and allocates a unique execution UUID per actual invocation, even when a provider call ID repeats. Initialization is lazy: no staging means no publication access/root lookup/DB reservation. Only the byte capability enters context; model-returned artifact metadata is never parsed as authority. The mandatory admitted-root resolver and foundation authorizer are still host responsibilities and must be supplied with actual policies at activation.

The lazy producer captures properties/bytes synchronously, validates paths/size/output bounds before allocation or awaits, tracks every started stage, closes the set at actual protected completion, and then finalizes the actual result. A rejected or malformed stage poisons the whole set without erasing a previously created workspace effect. The cancellation signal releases pending lazy initialization; a resolver that finishes later cannot publish. Private storage/DB operations retain foundation limitations; this does not prove arbitrary filesystem I/O can always be interrupted or that an in-flight external effect can be undone.

The server finalization observer carries separate publication success/failure metadata to trusted code. It is diagnostic, not an atomic durable error log, and its failure cannot erase committed publication records. There is no automatic producer retry or model follow-up. No consumer infers authority from copied result fields. At this component stage, existing legacy result artifacts are intentionally still returned unchanged, including forged metadata: they obtain no new DB publication but remain a legacy consumer concern until the coordinated cutover.

Final bounded regression union: 70 tests/331 assertions across six files, including 20 new lifecycle/integration tests; scoped TypeScript including new tests and dependencies, and seven-file lint pass. The original two API tests wrongly asserted one checkpoint rather than the required completion-before-checkpoint ordering; their failing logs remain. A later parallel fixture returned an empty final response and failed the pre-existing provider-final requirement; its log remains and its fixture was corrected. Self-review added invalid-first-stage reporting, pre-copy bounds, and abortable lazy initialization before these final gates. No live model/provider, native SDK, browser, channel or OS-confinement test is claimed by this gate.

This component is not activated by AgentService or server startup. Remaining work includes real current authorizers and complete sandbox-root inventory, the main/task/subagent/playground callers, selected-existing-file capture, durable session listing and HTTP/channel/share/history/UI consumers, retention/export/import and legacy migration. The separate owned-chat DB protocol is not assumed to exist here; run IDs alone do not constitute durable fencing. This patch plus producer/foundation components does not yet fix the full artifact attribution race, establish cold recovery, or support an Atlas/Hermes quality claim.
