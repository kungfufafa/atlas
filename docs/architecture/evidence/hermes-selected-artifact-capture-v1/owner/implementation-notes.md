# Explicit existing-file capture foundation

This independent scratch starts from the exact artifact-publication foundation source hash `6cf23f28cc6a9e7c0056c29e605850437e2175e93d63b80111e6f090d7df66dd`. It adds three files under `apps/server/src/services/`. It does not change the publication schema, DB evidence class, producer/finalizer, Bash/Python/custom-tool delivery, or any frozen source tree.

## Server API and authority

`createSelectedArtifactCapture(authorizedProfileRoot, signal?)` constructs a short-lived, server-only capture capability. The caller must already have authorized the current actor/profile and supply its canonical absolute profile root. The helper does not accept org/session/actor IDs, publication IDs, private storage paths, or a finalizer. Neither the factory nor its capability is installed in a tool, ToolContext, route, or model-visible object by this patch.

Trusted construction starts a static reader to acquire the root's device/inode identity through no-follow descriptor traversal. The returned closure accepts only an explicitly selected visible `artifacts/...` path and an optional cancellation signal. Each later read must match that captured root identity. Replacing the root does not refresh the closure's authority. This is an invocation-level filesystem identity, not a durable tenant/profile lifecycle identifier: do not serialize it or reuse it after profile recreation. The host must revalidate current actor/scope/intent around asynchronous capture/publication and construct a new capability for a newly authorized operation.

The returned value contains bounded bytes and a separate `selected_workspace_capture` evidence object: version, selected path, root device/inode, final file identity/size/link count/nanosecond mtime/ctime, digest, size, reader algorithm, and the fact that the observed metadata was stable. It explicitly does not say the tool or session generated these bytes. These server capture fields are not publication authority and are not added to the existing DB `sourceEvidence` union here.

## Anchored capture

The worker traverses the canonical root from `/`, opening every directory using `os.open(..., dir_fd=parent, O_DIRECTORY | O_NOFOLLOW | O_CLOEXEC)`. It retains those descriptors and checks their directory-name links and identities before accepting a root. It then opens every selected `artifacts/` parent relative to the held root/parent descriptors. Final open uses `O_NOFOLLOW | O_NONBLOCK | O_CLOEXEC | O_RDONLY` (and `O_NOCTTY` when present), so a FIFO does not block waiting for another opener. Only a regular file with exactly one hardlink and size at most 25 MiB is read.

This is not a realpath-then-final-no-follow implementation. There is no path-based fallback. Symlinks in any canonical root ancestor, selected parent, or final component are rejected. Root aliases such as macOS `/tmp` must already have been resolved by the trusted host to its authorized canonical spelling (`/private/tmp`) before construction; the helper will not follow them itself.

Capture reads at most 25 MiB plus one overflow byte in 64 KiB chunks. Before releasing bytes, it verifies the file descriptor metadata against its pre-read snapshot, verifies the named file still identifies that regular file, checks all held directory-name links, and checks metadata stability of the root and selected artifact directories. A changed or renamed directory can cause safe rejection even if an unrelated concurrent writer caused the change; no retry or automatic reselection occurs.

Paths must be bounded, relative, and lexically canonical under `artifacts/`; hidden components, `.sources`, empty/dot/traversal components, backslashes/control characters and artifact metadata sidecars are rejected. Sidecar exclusion is case-insensitive, including on hosts with case-insensitive filesystems. Files are never rewritten, removed or moved by this helper. Ordinary filesystem read-atime behavior is not an authored file update.

## Runtime and bounds

The implementation reuses `resolvePythonRuntime` from Atlas's existing Python tool and `resolveRestrictedExecutable`. Selection is the existing host-configured absolute `ATLAS_PYTHON_PATH`, managed `runtime/python/bin/python3`, then installed `python3` behavior. Docker already installs the managed Python runtime; the standalone setup script is `scripts/setup-file-runtime.sh`. Only Python standard-library operations are used; no package installation, C compiler, FFI library, `/proc` trick, privileged helper, or arbitrary additional executable is required.

The worker is fixed server source, passed with `-I -S` isolated startup, a minimal environment and cwd `/`. It executes no profile Python, user program, startup hook, package, or tool-provided source. It is a trusted static file reader, like Atlas's existing trusted runtime introspection and document workers; it is not a fallback that executes arbitrary code outside the normal Bash/Python confinement boundary.

The server caps concurrent workers at two, process duration at 10 seconds, stdin at 16 KiB, stdout at the maximum base64 representation plus 64 KiB, stderr at 8 KiB, and the decoded return at 25 MiB. It validates the response schema, canonical base64, selected path, expected root identity, byte count and SHA-256 before returning bytes. Overruns, malformed responses, cancellation, and nonzero exits reject without returning usable partial bytes. The fixed worker does not spawn descendants; cancellation/deadline termination waits for the child close event. Memory is bounded but includes JSON/base64 and decoded copies; this is not a zero-copy or per-host aggregate memory guarantee.

The tested host is macOS arm64, Bun 1.3.1, using the resolved Python runtime recorded in `runtime-evidence.json`. Linux is admitted only when the required POSIX/Python primitives exist, but a Linux execution gate was not run in this task. Windows and unsupported hosts fail closed; no Windows support is claimed. Canonical roots on other filesystems, special mounts, NFS or unusual timestamp behavior need their own deployment verification.

## Evidence and remaining limits

The focused test suite contains real Python subprocess reads and deterministic pipe barriers injected into a fixture copy of the same static worker. There are no production barrier arguments or environment switches. Tests replace a parent with a foreign symlink and a real foreign directory after the parent descriptor opens; replace the root before capture and after its descriptor opens; rename a parent away and back; replace the final file; add a hardlink after file open; and rewrite equal-length content after the first read chunk. Every such test asserts rejection with no returned base64 bytes. Ordinary success, later source rewrites, hidden/traversal/absolute paths, preexisting symlinks and foreign hardlinks, nonregular directory/FIFO files, empty/exact-limit/oversize files and pre-cancellation are covered.

Additional isolated test-runtime processes deliberately overrun stdout/stderr, stall past the actual 10-second deadline, and expose an in-flight cancellation boundary. These verify bounded rejection and process termination. They are transport/lifecycle fault fixtures, not ordinary Python producer tests or proofs of a hostile runtime sandbox. Tests clean their disposable workspaces; their source and full result logs remain in this evidence directory.

This establishes one exact captured byte sequence and rejection of observed unsafe or changed states. File metadata stability is not proof of a globally atomic filesystem snapshot, original authorship, semantic correctness, or absence of arbitrary hostile host writes. Unrestricted host/admin code can manipulate directories, files, runtime executables or DB/storage authority; mounted filesystems and inode reuse also exceed this short-lived identity contract. A normal concurrent writer may change a file after the final checks; that cannot alter the already captured bytes, but does not certify the source path still contains them.

No automatic publication, snapshot storage, delivery, public sharing or retry is enabled. The root integration must retain captured-existing-byte provenance, current authorization and explicit selection; it must stage exactly the returned bytes without rereading the mutable path. No end-to-end compute/native subscription/channel claim follows from these tests.

The first formatter command failed because the copied source lacked dependency links and Bun attempted temporary setup. Existing dependency links were then reused; no dependencies were installed. The first substantive 11-test run and its TypeScript gate passed, followed by the extended 17-test run. All initial and final logs are retained.
