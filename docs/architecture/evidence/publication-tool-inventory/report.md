# Atlas: izin pemuatan dan inventaris tool yang terikat ke sesi

Increment ini memperbaiki cara host Atlas mengizinkan pemuatan tool, mengikat definisi yang dipakai sesi, dan memeriksa ulang konfigurasi sebelum eksekusi serta publikasi artefak. Sumber berada pada salinan terpisah `/private/tmp/atlas-publication-tool-inventory-20260908/source`: **21 file berubah, delapan baru**. Mode baru belum diaktifkan pada bootstrap dan belum diadopsi ke sumber produksi. Dasarnya adalah [increment Chat files](../publication-chat-consumer/report.md).

Host kini memberi izin sebelum pemuatan JavaScript tersimpan, discovery dan metadata skill, grup MCP, probe/session/koneksi Composio, serta grup tool yang disuntikkan server. Hasil resolusi disalin dan dibekukan; token privat mengikat definisi final yang tepat ke host, organisasi, pemilik, profil, sesi dan workspace. Nama yang sama, objek hasil salinan, definisi dari resolusi lain, atau token parent pada child tidak menjadi bukti izin. Skill executable harus cocok dengan lokasi dan nama assignment. Assignment executable yang hilang, handler tidak dikenal, katalog MCP aktif kosong dan grup Composio yang seluruhnya kosong gagal secara eksplisit pada mode ini. Perilaku mode lama tetap diuji.

Sesi yang dipakai ulang memeriksa ulang assignment database dan identitas komponen host. Perubahan assignment, konfigurasi handler atau fungsi tool yang diuji menghentikan pemanggilan berikutnya sebelum provider. Child membuat inventarisnya sendiri. Kebijakan akar file menerima provenance tool terpilih serta seluruh descriptor loader yang disetujui. Akar file bawaan profil—termasuk direktori custom tool Super Agent—tetap menjadi minimum yang tidak bisa dihilangkan callback. Jika otoritas runtime tidak diketahui, publikasi gagal, sementara efek file yang sudah selesai dan receipt tool dipertahankan.

Review menemukan perubahan pemilik sesi saat pembacaan inventory masih ditunggu dapat lolos ke commit. Reproduksi awal mencatat satu commit yang seharusnya ditolak. Pemeriksaan principal asli kini dilakukan setelah pembacaan inventory, termasuk otorisasi commit. Validasi yang tertahan juga dapat dibatalkan tanpa menunggu hasil terlambat; rejection tetap diobservasi ketika callback membatalkan secara sinkron. Tidak ada pengulangan efek tool untuk memulihkan kegagalan publikasi.

Kasus Hono memakai AgentService, tool `write_file`, delegasi, penyimpanan dan pembacaan byte publikasi yang sesungguhnya dengan provider sintetis. Regresi lama juga menjalankan Bash lokal dengan sandbox proses Atlas tetap aktif. Pengujian loader JavaScript/skill/Composio memakai komponen palsu atau path yang tidak ada; tidak ada pemuatan modul eksternal atau koneksi MCP/Composio nyata yang dibuktikan. Tidak ada perubahan UI, sehingga QA browser dari increment Chat files tetap merupakan bukti terpisah.

Semua log percobaan sebelumnya dipertahankan, termasuk kegagalan komponen awal, dua kesalahan pembacaan receipt pada fixture native, celah otorisasi commit, dua kegagalan pembatalan tertahan dan tiga rejection setelah pembatalan sinkron. Batasnya tetap penting: identitas fungsi yang tepat **belum membuktikan byte modul, semua state di dalam closure, konfigurasi mailbox, atau seluruh otoritas runtime**. Kebijakan host wajib menolak sumber yang cakupannya belum diketahui. Pemeriksaan database bukan lease atomik. Callback akar yang gagal menolak publikasi, bukan membatalkan efek yang telah dilakukan tool. Katalog Composio yang tidak kosong belum membuktikan setiap assignment/action tersedia. Proses persisten, cache koneksi, pemulihan setelah restart dan kehabisan sumber daya belum dikualifikasi secara menyeluruh. Pemuatan yang mendapat izin tidak otomatis membuktikan runtime itu aman untuk aktivasi global.

Tahap berikutnya adalah membuktikan cakupan runtime yang terbatas dan konkret—termasuk perubahan sumber/config serta proses yang hidup melewati satu invocation—sebelum memilih aktivasi produksi. Kandidat C10, paket studi, batas akses reviewer dan penghentian renderer tetap dipertahankan. Tujuan perbandingan masih aktif dan belum tercapai: hasil valid terakhir [C9 adalah Atlas 44/54 versus Hermes 46/54](../hermes-native-files-v3-c9-confirmation/report.md). Tidak ada skor baru atau klaim setara/lebih baik dari increment ini.
