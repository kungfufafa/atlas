# Additive exploratory control public-output audit

This extension was authorized after the warm census criteria were fixed and some control endpoint inventories had been seen. It is exploratory, not preregistered before outcomes. The original warm criteria, scores and32-control inventory remain unchanged. At authorization the auditor had not reviewed the controls' public turn outputs/native effects for process judgments. Some frozen control flags and statuses were visible in inventory/checkpoint output; this is explicitly disclosed.

Review ALL32 scheduled cold/identity control arms, including successful endpoints. Read only finalized end evidence; no current mutable state, holdout, inference, tests, reruns or source/score changes. Keep every exact ID, condition, harness, control type and identity context, public turn outputs, actual native effects, snapshots and raw evidence hashes. Partial checkpoints state reviewed/ended/scheduled counts. Do not pool these judgments or outcome rates with the64 warm-arm census or imply whole-batch reliability from incomplete coverage.

Apply the warm audit's distinctions to controls where relevant: explicit persistence claims require supporting actual effects before final public turn response; plans/attempts/pending approval are not success claims. A confirmed wrong/unsupported positive assertion differs from null/unknown. Keep factual recall, final envelope, resource certification, lifecycle, false persistence, intermediate errors and later repair distinct. Frozen finalContract/boundaryValid/falseCompletion are composite flags, not pure format/isolation/fabrication detectors. Missing effects alone are uncertain when existing state supports a claim. Earliest streamed-fragment timing is not independently reconstructed.

The intended fresh-state/identity boundary changes interpretation. Cold recall intentionally uses fresh native state; training data remaining in sessionA state is not a failed deletion, and absence from freshB is not independent-fact loss. Same-profile transfer in Atlas is not automatically unauthorized disclosure; Hermes home/installation separation is not proof of an in-product tenant ACL. Distinguish native curated DB/file memory from authorized conversation history and their observed audiences. Do not infer security from generic positive/negative transfer counts. Requested active withdrawal differs from permanent erasure; do not claim global erasure from a single file. Default unsaved facts are not automatically defects.

Inventory and manually classify every completed control arm, not only cases with model errors. Any unsupported-claim observation must cite exact public text and actual evidence; distinguish confirmed effect, manual interpretation, uncertainty and out-of-scope ancillary advice. This is descriptive process review only, no changed primary endpoints, aggregate superiority/equivalence claim or causal provider/model inference.
