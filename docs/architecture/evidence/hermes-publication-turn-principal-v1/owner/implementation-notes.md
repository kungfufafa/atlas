# Per-turn publication identity and admission

This isolated component extends reviewed consumer V2. It is not activated in AgentService, routes, tools, or the root C5 candidate. There were no provider calls and no benchmark changes.

Each send/sendStream captures an optional host-owned toolExecutionGuard and toolExecutionLifecycle before the first await. Undefined lifecycle inherits the session default; null explicitly clears it for that turn. A guard receives a frozen shallow copy of the original host tool context and the actual dispatched tool name. Existing beforeToolCall completes first, then the fresh guard is awaited before the protected tool's run method. No lifecycle or guard is read from model JSON. No parallel conversation ownership or deep immutability of referenced callback objects is asserted.

createPublicationTurnPrincipal derives org/profile/session and effect user from a persisted session. It copies the authenticated invoker, preserving a channel worker's transport identity separately from the human owner used in tool context and publication scope. The real current session ACL still receives the original authenticated actor. It checks bound identity both before and after awaited ACL resolution and rejects mismatching contexts/publication scopes. Human admins cannot invoke another user's session through this helper.

The new tests cover sequential cached-session reuse across API/native dispatch and send/stream, lifecycle override/clearing/default restoration, actual effects denied by awaited guards, current owner/membership/viewer changes, worker channel mismatch, mutable input actor copies, and forged scope/context. Database fixtures use the real SQLite adapter and AgentService ACL.

Preserved counterexamples and fixture corrections:

- Before the per-turn seam, the four new API/native x send/stream tests failed against byte-exact consumer V2 chat.ts. The final chat.ts was restored in finally; bindings are retained.
- The initial principal had two real owner-change-during-ACL failures. Its third failure was a fixture mistake: SQLite upsert deliberately preserves an existing owner when supplied null. The corrected fixture deletes and creates a new ownerless row and verifies persisted null. That corrected run retains exactly two real failures. Adding the post-ACL identity check passes them. This does not turn asynchronous authorization into an atomic transaction.
- Initial guard-order fixtures returned empty final provider text and failed before assertions. That log is not an admission counterexample. With valid fixture final text, exact prior chat.ts produced one actual effect in both API/native cases despite revocation during the old guard. These two assertion failures are retained; reversing guard order denies both effects.
- New fixture type errors (missing streamChat and synchronous run) are retained and corrected. Earlier full production typecheck failed because copied workspace platform dependency links were absent. Four local platform dependency directories were copied as links and their Atlas package links rebound to this isolated source; no packages were installed and no root dependency was edited. Both the original failure and the exact added link inventory are retained.

Final bounded gates: 65 tests / 322 assertions across five files, including 28 new tests across two files; scoped typecheck, production typecheck, four-file lint and read-only component patch checks. Counts do not include earlier overlapping runs.

Limits: This is a pre-tool effect guard, not pre-loader/pre-spawn confinement or authorization for the legacy artifact pre-scan. Lifecycle begin failure remains nonfatal to protected tool execution, so strict denial must use the awaited guard. A current authorization check can race later revocation; no durable lease, atomic ACL/effect transaction, cancellation-before-model guarantee, task/delegate/automation identity mapping, grant receipt, root-disjointness proof, UI cutover, or private-store activation is included. Future integration must preserve the separate per-request consumer read/revoke access path, including viewer reads; this helper initially requires publish permission and is specifically for a tool-bearing turn.
