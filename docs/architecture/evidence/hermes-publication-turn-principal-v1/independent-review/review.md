## Source findings

`packages/agent/src/chat.ts:522–601` reads the host guard and lifecycle override before the first await in both send modes. Each call gets a fresh guard closure. Null disables the default for that turn; omission restores the session default on a later turn. No JSON input field is consulted for authority. `withAdditionalToolGuard:610–625` preserves and awaits the existing guard first, then awaits the fresh guard immediately before returning control to protected execution. If either rejects, actual tool execution is denied. The previous guard-first reversal defect is addressed by the final order: an existing awaited guard can change authorization, which the fresh guard then sees.

The lifecycle and context are forwarded through the already-reviewed common API/native executor. The executor retains mandatory `executeProtectedTool`, passes only the publisher to a fresh execution context, observes protected success/failure before distillation, and clears inherited publishers when no lifecycle is active. Native provider callbacks use the common dispatcher and checkpoint behavior; this patch adds no provider-supplied principal, cross-turn provider-ID authority or native SDK bypass. The native tests here are fake-provider callbacks through the actual agent path, not a subscription runtime or real provider experiment.

`apps/server/src/services/publication-turn-principal.ts:32–46` copies the authenticated invoker and derives profile and effect user from a persisted, org-matching session. The returned object, invoker and scope are frozen. `authorizePublication:58–76` requires exact effect actor/org/profile/session, verifies persisted identity before authorization, delegates actual current ACL with the original invoker identity/channel, then verifies persisted identity again. The worker's local transport user remains separate from the human effect user. The adapter changes only the scope actor passed to the existing invoker-bound authorizer; it does not manufacture a human SessionActor or discard the worker channel.

The inherited authorizer checks current organization/profile/user/membership and actual AgentService action ACL. Human admins cannot invoke another user's session through the principal factory because initial admission requires publish/invoke permission. Worker ACL remains scoped to the persisted external channel and real human membership, and refuses Super Agent access. `validateContext:86–95` compares only the bound user/org/profile/session, then performs the same current publish check. It does not silently repair a mismatching context.

## Integration qualifications

The guard receives a frozen **base session context snapshot**, captured before sendMessage adds the current runId, composed turn signal and clientOrigin. It is sufficient for this helper's exact scope comparison. It is not the final dispatch context or an actual filesystem grant receipt. A future runtime admission guard must not infer current run/signal or dynamic temporary roots from it. Nested referenced callback objects are not deeply frozen, and the selected lifecycle is a captured object reference, not an immutable deep copy.

`validateContext` already invokes `beforeToolCall`; an integration should not add the same call twice merely because both APIs are exposed. Keep the existing guard first and fresh current check last. This supersedes the **earlier planned**, parent-reported new-guard-first order recorded in the separate sealed activation-design audit; that historical document remains unchanged.

The post-ACL re-read closes the tested owner-change window, not all authorization races. Membership/channel/org state can still change after its checks, and a same-ID deletion/recreation with identical fields has no generation/lease proof. These are explicitly outside this component's atomicity claim. The helper is initialized with publish permission and must not replace the separate request-bound consumer factory for viewer read access.

The guard runs before tool.run, after existing approval handling and the legacy artifact pre-scan. It does not deny metadata imports, local MCP startup, unsafe host runtimes, or arbitrary-code spawn before those earlier operations occur. Lifecycle begin errors remain nonfatal by design. No private-store confinement, AgentService/HTTP activation, persisted-wrapper option snapshot, UI/channel delivery cutover, explicit existing-file selection, non-chat durable scope, durable lease or Hermes parity follows from this review. Those remain separate integration gates.
