# MCP: izin dan koneksi diperiksa sampai dispatch

Integrasi dalam salinan sumber terpisah mengikat panggilan MCP ke koneksi yang benar-benar ditunggu, mempertahankan sinyal pembatalan asal, dan memeriksa izin pengguna serta assignment dalam satu batas database sebelum masuk ke SDK. **319 tes unik / 1.487 assertion lulus**, termasuk **113 tes baru**. Typecheck dan lint mencakup 13 berkas TypeScript yang berubah. Ini bukti perilaku kode; hasil perbandingan terakhir tetap **Atlas 44/54 dan Hermes 46/54**, sehingga klaim setara/lebih baik belum terbukti. [Hasil C9](../hermes-native-files-v3-c9-confirmation/report.md).

Manager memberikan objek pengikat privat untuk satu dispatch. Objek itu merujuk ke entri koneksi tertentu, bukan sekadar ID server. Manager menolak objek palsu, objek dari manager lain, pemakaian ulang, koneksi yang sudah ditutup/diganti, dan pembatalan asal. Satu pemanggil yang membatalkan tidak membatalkan startup atau koneksi bersama. Sinyal tiap request menggabungkan pembatalan pemanggil dan lifetime koneksi. Promise dari SDK dan callback diamati segera agar penolakan tidak luput bila callback membatalkan secara sinkron.

Bridge memeriksa katalog sebelum startup, menjalankan guard konteks sesudah startup, lalu membaca ulang assignment. **AgentService selalu menambahkan pemeriksaan DB akhir** yang menyatukan org aktif, profil, pengguna asli, peran/admin terkini, akses Super Agent, assignment MCP, status enabled, konfigurasi/transport, dan schema tool. SQLite memegang snapshot sampai callback memanggil validasi koneksi dan masuk ke SDK secara sinkron, lalu melepas transaksi sebelum menunggu hasil request. Adapter memori tidak menunggu di antara pemeriksaan dan callback. Identitas pengguna terikat ke pengguna saat tool di-resolve; mengganti userId dalam konteks tidak menggantinya.

Tiga tes baru dalam kelompok 101 memakai resolusi AgentService dan loop eksekusi tool yang sebenarnya, dengan harness/manager tiruan. Ketiganya menolak pencabutan peran atau assignment selama pembacaan katalog terakhir serta penggantian userId ke pengguna lain yang juga valid. Ketika hanya AgentService dikembalikan ke versi sebelumnya, ketiganya justru melakukan dispatch dan gagal. Uji SQLite dua koneksi juga menunjukkan penulis lain tertahan selama callback dispatch sinkron, lalu bisa menulis ketika promise hasil tool masih tertunda. [Gate final](../../../../outputs/hermes-evidence/2026-09-08/mcp-bridge-dispatch/final-gates.json), [inventori tes](../../../../outputs/hermes-evidence/2026-09-08/mcp-bridge-dispatch/test-inventory.json).

Hitungan tidak menggandakan percobaan ulang. Satu tes lama yang memulai worker MCP difilter sebelum eksekusi dan tidak dihitung lulus. Semua hasil gagal dipertahankan: baseline bridge 2 lulus/12 gagal; SDK abort sinkron 0/1; sinyal asal 0/2; urutan key scope 0/1; serta integrasi AgentService versi lama 0/3. Gate DB pertama 45/2 gagal akibat fixture yang memakai upsert untuk state importing; koreksinya memakai reservasi impor yang sebenarnya. Empat error tipe berasal dari metadata description fixture yang kurang. Empat kegagalan regresi lain berasal dari mock yang masih memakai API dispatch lama; seam mock diperbarui tanpa mengurangi assertion allowed/denied. [Catatan percobaan](../../../../outputs/hermes-evidence/2026-09-08/mcp-bridge-dispatch/retained-attempt-notes.json).

Review terakhir dilakukan rekan satu tim yang menulis tes bridge/DB; bukan review buta untuk perbandingan model. Seluruh 13 hash final cocok, termasuk 10 referensi gate 87 yang tetap identik. Root memeriksa ulang referensi dan fixture. Tidak ada blocker tambahan pada batas implementasi ini. [Review v3](../../../../outputs/hermes-evidence/2026-09-08/mcp-bridge-dispatch/agent-dispatch-review-v3.json), [readback](../../../../outputs/hermes-evidence/2026-09-08/mcp-bridge-dispatch/handoff-reference-readback.json).

Batas bukti tetap penting: generic bridge yang tidak diberi callback DB keenam masih memiliki pemeriksaan lebih lemah; integrasi AgentService memasangnya. Callback transaction adalah fungsi host tepercaya. Batas authorization berakhir pada masuknya dispatch sinkron, bukan penyelesaian efek di layanan luar. SDK/transport/worker MCP dalam pengujian manager masih tiruan; pembatalan tidak membuktikan efek eksternal yang sudah dimulai berhenti. Uji receipt memakai persiapan nyata dengan SDK tiruan. Hanya regresi Bash biasa menjalankan proses nyata dengan sandbox Atlas. Tiga uji AgentService bukan bukti Hono/provider/runtime subscription nyata.

Sumber berada di `/private/tmp/atlas-mcp-bridge-dispatch-20260908/source`: 2.192 berkas reguler, 177 symlink; delta 13 berkas (5 baru, 8 diubah). Sumber produksi utama, kandidat C10 tetap, bootstrap, kontrol Hermes, dan admission studi tidak diubah. Tidak ada panggilan model/provider, renderer, worker MCP nyata, atau pelepasan reviewer studi. [Patch increment](../../../../outputs/hermes-evidence/2026-09-08/mcp-bridge-dispatch/changes.patch), [patch kumulatif C10](../../../../outputs/hermes-evidence/2026-09-08/mcp-bridge-dispatch/combined-from-c10.patch), [identitas sumber](../../../../outputs/hermes-evidence/2026-09-08/mcp-bridge-dispatch/source-changes.json).

Berikutnya perlu menguji Client SDK terpasang dengan transport JSON-RPC dalam memori, lalu memeriksa dispatch endpoint Composio yang masih memakai jalur terpisah. Itu memperkuat bukti integrasi SDK tanpa memulai provider, worker, atau renderer. Pengujian kualitas model baru tetap menunggu persyaratan inspeksi yang diterima.
