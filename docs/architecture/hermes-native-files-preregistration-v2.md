## Delivery selection and grading

Delivery is selected and written to an immutable selection record **before** invoking any artifact oracle. No directory scan, expected-value comparison or grader result participates in selecting a candidate.

For documents/CSV, accept one unambiguous final user-visible artifacts/ path, including a Markdown link, inline code path, clear bare path or an absolute file path within that actual workspace. Equivalent safe relative spellings are normalized. Multiple distinct candidates, invalid escaping candidates, unsupported URI mappings or no resolvable delivery fail selection. Repeated mentions of the same path are one candidate. If final text supplies no candidate, Atlas may use one unambiguous native published artifact receipt; multiple native published candidates fail. Hermes's generic terminal output or a path found only by scanning workspace files is not a published artifact receipt. An explicit final path takes precedence over receipt candidates, so a correct unmentioned file cannot rescue a wrong declared delivery.

The code task's fixed deliverable is app/money.py, specified by the request, and it is never substituted with another file. Its public test remains immutable. This fixed source-edit destination differs from choosing among document exports. Both model workspaces receive the identical input/code-contract.json exported from the grader's shared file-code-contract.py; the request explicitly designates it as the mandatory API contract. It discloses exact admitted imports, members, builtins, names and function signature rules. The fixture, private manifest, frozen study and grader receipt bind the same independently computed contract hash. Expected test values are absent from the contract. Read-only private originals mark intended preservation; workspace copies have the matched writable mode declared above, and source-hash verification rejects any unauthorized alteration. This is a restricted pure-currency-function task, not general Python or software engineering performance.

Before semantic grading, bind the selected regular file to exactly one matching native workspace snapshot hash and require a successful native effect receipt (Python, terminal/process, file write/edit/patch). Reject symlink components, hardlinks, oversized files and changing bytes. A generic successful effect receipt establishes native execution alongside the resulting file; it does not by itself establish correctness or prove which individual instruction caused the file.

The independent artifact oracle verifies the selected path's actual bytes and format, required facts/cells/content, permitted mutation scope and preserved source hashes. Parser/decompression/dimension limits are explicit in the oracle. Serialization metadata does not require byte-for-byte OOXML output equality; requested structural and styling preservation does. Formula preservation is checked, but cached-value recalculation is not claimed. Native artifact receipts and filesystem hashes remain available for audit, distinct from semantic correctness.

Primary success requires all of: completed execution within budget, the exact prescribed user-turn sequence in an initially empty native session, identical copied input hashes, valid cleanup/inspection eligibility, one valid delivery selection and a passing independent artifact/source oracle. A polished final answer with a wrong or missing file fails. Final JSON is not required and is not a score. Artifact failure, source-integrity failure, invalid/ambiguous delivery, invocation error, unsupported operation and budget exhaustion are reported separately. Limited forbidden-positive-phrase checks are diagnostics; they are not a comprehensive truthfulness classifier for every sentence.

Hidden code grading uses the separately reviewed file-code-check.py and first enforces the disclosed finite admission contract. A trusted parent keeps the private expected cases. Each independently OS-sandboxed child sees only the copied read-only candidate source and one input string, never expected values or the full test suite. Network/process forking is denied and each child gets a fresh private writable temporary area. The parent compares actual outputs/errors with hidden expectations and writes a strict receipt bound to candidate source SHA, test-suite SHA, admitted contract SHA and the independently frozen parameterized sandbox-policy SHA. Concrete expanded policy hashes and case evidence are retained separately. The oracle receives the expected policy hash from the freeze, not from the candidate or its receipt. Budget: one second per case, at most 30 seconds of code grading; grading latency is recorded separately from the 300-second inference trajectory and is identical for both harnesses. Candidate stdout and file output are bounded; there is no enforced Python allocation limit or universal purity/security claim. An unavailable/failed grader cannot be replaced with a guessed pass or an agent's own test claim.

No visual renderer is currently part of the acceptance gate. DOCX/PDF/PPTX/XLSX structural/content correctness does not establish no clipping, perfect pagination, visual fidelity, accessibility, formula display freshness or production presentation polish. A future visual quality claim requires a separately implemented, frozen rendering/adjudication gate.
